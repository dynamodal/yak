# Notes editor: decisions to review

The Notes page was redesigned in the style of Obsidian (2026-10-16), focused on note-taking rather than code editing.

| # | Decision | Why | How to change it |
| --- | --- | --- | --- |
| NE1 | **Live mode is the default**: Markdown marks (`#`, `**`, `` ` ``, `[[ ]]`, list dashes, `>`) are hidden except on the line with the cursor; headings, bullets, quotes and inline code are styled; task boxes are clickable and tick the text (`- [x]`) | Obsidian's Live Preview: the note reads finished while the file stays plain Markdown | `livePreview` in `src/notes/editor.ts` |
| NE2 | **Properties are shown once.** In live mode the YAML front matter is hidden from the text (an atomic block the cursor skips) and edited in the compact Properties table | Showing both took a third of the screen and duplicated every value | `hiddenFrontMatter` in `editor.ts`, `Properties.tsx` |
| NE3 | **Per-device "Properties in document" choice**: visible (table, default), hidden, or Source mode (YAML and Markdown exactly as stored, monospace, no table), in the note's "…" menu | Obsidian has the same three options; some people want the raw file | `readDisplay`/`writeDisplay` in `Properties.tsx` (localStorage) |
| NE4 | **Property values get a fitting control**: lists and tags as chips (Enter or comma adds, Backspace removes the last), `[[links]]` clickable, `YYYY-MM-DD` with a date picker, true/false as a checkbox, nested values read-only (edit in Source) | Typed controls as in Obsidian's property types, without a type registry yet | `PropValue` in `Properties.tsx` |
| NE5 | **New `tags`, `aliases`, `projects`, `contexts`, `cssclasses` properties start as lists** | They are lists in Obsidian and TaskNotes; a text property could never become one in the UI | `LIST_PROPERTIES` |
| NE6 | **Inline title** (the file name without `.md`) replaces the path field; the folder shows as breadcrumbs; moving to another folder is "Move to…" | Obsidian's inline title; a path field read like a file dialog | `NotePane` in `NotesView.tsx` |
| NE7 | **Delete with Undo** (toast, 8 seconds) instead of a two-step confirm; Undo restores the soft-deleted note | Matches the Toggl-familiar plan (U1) and is faster; nothing is lost because deletes are soft | `remove` in `NotesView.tsx`, `restoreNote` |
| NE8 | **File tree**: icons, toolbar (new note, new folder, collapse all, Open… Ctrl K), drag and drop of notes and folders onto a folder or empty space (top level), and a "…" menu per row with New note here, New folder here, Rename, Move to…, Delete | Obsidian's file explorer; the menu and the "Move to…" dialog are the keyboard and touch alternatives, since HTML drag and drop does not work with touch | `Tree.tsx`, `MoveDialog.tsx`, `planMove` in `paths.ts` |
| NE9 | ~~A new folder starts with an "Untitled" note in it~~ Replaced by NE17 (2026-10-17) | The note was a stand-in for a folder that could not exist on its own; it made the new-folder box ask for the file's name | — |
| NE10 | **A move that would land on an existing note, or a folder into itself, is refused** with a message; dropping where it already is does nothing | No silent overwrites; same rules as renaming a folder | `planMove` |
| NE11 | **Superseded by N23 (links are rewritten on move).** Was: links do not change when a note moves: `[[Name]]` links resolve by name, so they keep working; `[[Folder/Name]]` links break | Link rewriting on rename and move is planned with notes as documents (`sync-model.md`, M14) | — |
| NE12 | **Linked mentions and outgoing links** move to a collapsible footer under the note | Less noise while writing; mentions open by default when there are any | `NotePane` footer |
| NE13 | **Editing shortcuts as in Obsidian and VS Code**: Ctrl+B, Ctrl+I, Ctrl+Shift+X, Ctrl+` wrap or unwrap the selection or the word; Ctrl+L and Ctrl+. cycle text → bullet → task → done → text; Ctrl+Enter ticks a task (or opens the link under the cursor); Ctrl+K wraps in `[[ ]]`; a list in the note menu ("Keyboard shortcuts") | People coming from Obsidian expect them; the commands are plain functions with unit tests | `editor-commands.ts`, keymap in `editor.ts` |
| NE14 | **Headings on Ctrl+Alt+1…6 and Ctrl+Alt+0**, not Ctrl+1…6 | Chrome and Edge keep Ctrl+1…8 for switching tabs and do not let a page take them; Google Docs uses Ctrl+Alt for the same reason | keymap in `editor.ts` |
| NE15 | **Several cursors**: Alt+click, Ctrl+Alt+↑/↓, Ctrl+D (next occurrence), Ctrl+Shift+L (all occurrences), Esc for one cursor | VS Code's keys; Alt+click because Ctrl+click opens links | `allowMultipleSelections`, `clickAddsSelectionRange` in `editor.ts`; adds `@codemirror/search` (already in the bundle through `codemirror`) as a direct dependency |
| NE16 | **Find a note is Ctrl+O (Obsidian) or Ctrl+P (VS Code, Notion), no longer Ctrl+K**; Ctrl+K is "insert link" as in Obsidian, Notion and most editors; Ctrl+Shift+K stays "delete line" | The owner's choice (2026-10-16). The page takes over the browser's Ctrl+O (open file) and Ctrl+P (print) while Yak is open; Print stays in the browser menu. Ctrl+P moves to a command palette if one is added | `src/notes/index.ts` |
| NE17 | **Folders can exist with no note in them.** "New folder" opens a name box in the tree (suggesting "New folder"; Enter or leaving the box keeps the name, Esc cancels) and makes an empty folder. Empty folders are stored in a `folders` map of the space document (keys are folder paths, values plain `true` or `false`). A folder with notes needs no entry. Rename and move carry the entries; "Delete folder" (with Undo) is offered only on empty folders | The old workaround, a stray "Untitled" note, showed the file's name in the box (owner report). Plain values per path mean two devices making the same folder cannot lose a record | `foldersMap`, `addFolder`, `moveFolderEntries` in `note-store.ts`; `createFolder` in `NotesView.tsx`. Backups keep empty folders in the Yjs state; the readable Markdown files cannot show an empty folder |
| NE18 | **New notes get `dateCreated`** (an ISO timestamp) in their front matter, never added on edits or to existing notes | The same field and format that task notes already write (`tasks.ts`); TaskNotes' field names are configurable, so a different name is a one-line change | `newNoteText` in `note-store.ts` |
| NE19 | **The tag selector is always shown** in Properties, with the space's existing tags as suggestions (not the `task` marker). The `tags:` line is written when the first tag is picked and removed with the last one. A `tags` value that is not a list is edited as plain text | The owner wants tagging easy without YAML appearing by itself | `Properties.tsx` |
| NE20 | **The editor is a bordered surface** whose border takes the accent colour and a ring while it has focus | The text area looked like the page, so it was unclear it could be edited (owner report) | `.note-editor` in `notes.css` |
| NE21 | **Inputs that autofocus do so before the first paint** (`CommitInput` uses a layout effect) | A fast typist, or a browser test, lost the first key typed into a new name box | `common.tsx` |
| NE22 | **One sidebar row (#135; replaces the NE8 toolbar):** the search field, a "+" menu (New note, New folder, Today's note, This week's, This month's) and a "…" menu (Collapse or Expand all folders, "Find a note…" for the switcher). The "Open… Ctrl O" button is gone; Ctrl+O and Ctrl+P still open the switcher (NE16) | The five rows of controls above the tree cost about 200 px; "Find a note" by name inside the search field is a follow-up, so the menu keeps the switcher reachable until then | `notes-toolbar` in `NotesView.tsx` |
| NE23 | **The editor has no border or background (replaces NE20):** it sits on the page like text. The Properties rule under the title and the caret show where to type | #135: a bordered box read as a form field; the title, Properties and the page already frame the note | `.note-editor` in `notes.css` |
| NE25 | **The borderless editor shows focus (#163; amends NE23):** no border at rest, a faint hover tint, and while it has focus an accent line on the left edge with a soft accent background | NE23 removed the focus state that #46 (B3) added, so clicking in changed nothing | `.note-editor` in `notes.css`, `notes.mjs` |
| NE24 | **Timestamps in Properties read in the device's locale** ("Mar 25, 2026, 8:30 AM") instead of raw ISO; a click shows the stored text to edit. Date-only and `YYYY-MM-DDTHH:mm` values keep their native pickers (N28). On a phone (≤ 48 rem) the Properties table starts collapsed until the person opens it once (then the choice is remembered, as before) | Raw `2026-03-25T08:30:00.000Z` is noise; on a phone the text should start at the top | `MomentValue`, `readOpen` in `Properties.tsx` |
| NE26 | **The search field finds notes by name (#157):** a note whose title or `aliases` holds every search word ranks above full-text hits; Enter in the field opens the first result. The sidebar menu's "Find a note…" item is gone; Ctrl+O and Ctrl+P still open the switcher (NE16, amends NE22) | One field instead of two ways to find a note; name matches first because people type names | `searchNotes` in `search.ts`, `NotesView.tsx` |
| NE27 | **A formatting bar shows on phones (≤ 48 rem) while the editor has focus (#68):** Bold, Italic, Heading (cycles H1→H2→H3→plain), Bullet, Checkbox (the Ctrl+L cycle), Link, Indent, Outdent. It is fixed to the bottom and lifted by the `visualViewport` gap so it sits above the on-screen keyboard; buttons cancel `mousedown` so the editor keeps focus | Reuses the editor commands; no toolbar on desktop where shortcuts exist | `NoteEditor.tsx`, `.note-format-bar` in `notes.css` |
| NE-103 | **The editor shows its area at rest (#103; amends NE23/NE25):** a 1px `--border` line and a faint `--surface-2` tint; hover deepens the tint, focus keeps the accent border, tint and left line | Owner: the box matched the page until hovered or focused, so it was not clear where to type; the tint and thin line keep it from reading as a form field (the NE23 worry) | `.note-editor` in `notes.css` |

Not built yet: reading view, tabs and split panes, a right sidebar (outline, backlinks), multi-select in the tree, link rewriting on rename, embeds and callouts.
