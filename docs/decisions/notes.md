# Decisions: notes and tasks (branch `feat/notes`)

Choices made while building the notes and tasks module without the owner present.
Each row says what was chosen, why, and what it would take to change it.

| # | Decision | Why | To change it |
| --- | --- | --- | --- |
| N1 | **A task is a note whose front matter `tags` contains `task`** (case-insensitive; a list or a comma- or space-separated string) | This is TaskNotes' default rule, so a vault opened in Obsidian with TaskNotes shows the same tasks | `isTaskProps` in `src/notes/tasks.ts`; TaskNotes also supports "is in folder" or "has property", which would be another branch there |
| N2 | **Status values `open`, `in-progress`, `done` by default; any other value is read and shown as its own board column**. `done`, `completed`, `complete`, `cancelled` and `canceled` count as finished | Matches TaskNotes' defaults and keeps custom statuses from other tools | `DEFAULT_STATUSES` and `COMPLETED` in `tasks.ts`; a settings screen for custom statuses comes later |
| N3 | **Marking a task done sets `status: done` and `completedDate: YYYY-MM-DD`; reopening sets `status: open` and removes `completedDate`**. `dateModified` is not written | `completedDate` is TaskNotes' field; writing `dateModified` on every change would add churn to every edit, and the record already has `updated_at` | `completionChanges` and `statusChanges` in `tasks.ts` |
| N4 | **Quick add writes `Tasks/<title>.md`** with `title`, `status: open`, `priority: normal`, optional `due` and `contexts`, `tags: [task, …]`, `dateCreated`. It understands `@context`, `#tag`, `due:YYYY-MM-DD` and `!high` | TaskNotes' default folder and field names; the title also stays in the file name, so it reads well in Obsidian | `TASK_FOLDER`, `newTaskText` and `parseQuickAdd` in `tasks.ts` |
| N5 | **Front matter is edited by rewriting only the changed property's lines** (found with the `yaml` CST), then reduced to the smallest splice (common prefix and suffix). Comments, key order, quoting and other properties stay byte for byte | A whole-block rewrite would replace text that another device may be editing at the same time and lose its edit; a splice limited to one value merges with concurrent body edits and with changes to other properties (unit-tested with two `Y.Doc`s) | `propertyEdit` in `src/notes/frontmatter.ts`. Two devices changing the *same* property at once may still interleave characters; last-writer-wins per property would need the properties in a `Y.Map`, which breaks "the Markdown text is the single source of truth" |
| N6 | **Invalid YAML front matter is never rewritten**: the properties panel and table refuse the edit and say why | Guessing would destroy what the user wrote | — |
| N7 | **Paths are compared case-insensitively** for conflicts and for "name already used" | Vaults also live on Windows and macOS file systems, which are case-insensitive | `pathKey` in `src/notes/paths.ts` |
| N8 | **Two notes with the same path are both kept and flagged** ("conflict" badge in the tree, banner in the note with a link to the other note). Renaming to a path already in use on this device is refused | Records are keyed by UUID (decision F6), so a concurrent creation on two devices cannot lose either note | — |
| N9 | **Folders exist only as path prefixes.** Renaming a folder rewrites the `path` of every note under it in one transaction; an empty folder cannot exist | Same model as files in a vault; no separate folder records to keep in sync | A `folders` map would be needed for empty folders |
| N10 | **Obsidian syntax supported:** `[[target]]`, `[[target#heading]]`, `[[target\|alias]]`, `![[embed]]` (recognized as a link, not rendered), inline `#tags` (at least one non-digit, nested `a/b`), front matter `tags`, backlinks. Links and tags inside code are ignored. Not yet: callouts, block references (`#^id`), embeds rendered inline, aliases from front matter `aliases` | The common core first; rendering embeds and callouts needs a live-preview mode | `src/notes/links.ts` |
| N11 | **Link resolution follows Obsidian:** full path first, then a path ending in the target, preferring the linking note's folder, then the shortest path. An unresolved link creates the note at the vault root (or at the path written in the link) | Same results as Obsidian, so links keep working in both | `makeResolver` and `pathForLinkTarget` in `links.ts` |
| N12 | **A click on a link in the editor opens it, unless the cursor is already on that line** (then it places the cursor, so the link can be edited); Ctrl/Cmd-click always opens; Ctrl/Cmd+Enter opens the link at the cursor. The Links panel lists every link as a button | Close to Obsidian's live preview, without making links impossible to edit | `editorExtensions` in `src/notes/editor.ts` |
| N13 | **The editor shows the raw Markdown, front matter included**, with the properties panel above it | Plain source mode is reliable with concurrent edits; a live-preview mode can come later | — |
| N14 | **CodeMirror is mounted in a shadow root and themed in code.** The architecture notes say CodeMirror uses constructed style sheets, but its `style-mod` does that only inside a shadow root; in the document it adds a `<style>` element, which `style-src 'self'` blocks (found by the browser test). Inside a shadow root it uses `adoptedStyleSheets`, which the policy allows. Colours come from the app's CSS variables, which inherit into the shadow root | Keeps the strict CSP without `'unsafe-inline'` | `createEditor` and `theme` in `editor.ts`; `architecture.md` should be corrected when the stack is integrated |
| N15 | **CodeMirror is loaded on first use** (its own chunk, about 177 KB gzip) | The main bundle drops from 670 KB to 162 KB, so the timer starts faster | Import `../editor` statically in `NoteEditor.tsx` |
| N16 | **Undo uses a `Y.UndoManager` per open note** (CodeMirror's own history is not loaded), so Ctrl+Z undoes only this device's edits, including property changes | Undoing a remote edit would surprise the user and fight sync | — |
| N17 | **The table view is a generic front matter table** (rows: tasks or all notes; columns: every property, task fields first; sort by header; filter with words or `key:value`, `key:` for empty and `key:*` for set; click a cell to edit). It is not saved as a `.base` file | Covers the Bases use case without implementing the Bases file format | `TaskTable` in `src/notes/views/TasksView.tsx` and `tableColumns`, `filterRows` and `sortRows` in `tasks.ts` |
| N18 | **Kanban moves use native HTML5 drag and drop, with ← and → buttons on every card as the keyboard and touch alternative** | HTML5 drag and drop does not work with touch on most mobile browsers, and it is not keyboard accessible | — |
| N19 | **"Start timer" emits `timer:start-request` with the task title as the description and the note id as `taskId`.** TaskNotes `projects` are wikilinks to notes, not time-tracking project ids, so no `projectId` is sent | The notes module must not import the time module | Map `projects` to a project id in the time module if wanted |
| N20 | **Ctrl/Cmd+K anywhere opens the quick switcher** (it switches to the Notes view first); Enter opens, Shift+Enter or Enter with no match creates a note | Same key as most apps' command palettes; Obsidian's Ctrl+O opens the browser's file dialog | Listener in `src/notes/index.ts` |
| N21 | **`updated_at` is stamped 1.5 s after the last local keystroke**, not on every keystroke | Avoids one extra map update per character | `NoteEditor.tsx` |
| N22 | **Declared `@codemirror/commands`, `@codemirror/language` and `@lezer/highlight` in `package.json`.** They were already installed as dependencies of `codemirror` and `@codemirror/lang-markdown`, so no new code is shipped; they are declared because the code imports them directly | Imports should not rely on hoisting | — |
| N23 | **Links follow a renamed or moved note** (owner rule, 2026-10-17). Links that reach a moved note, and links inside a moved note, are rewritten to the shortest unambiguous spelling (the full path when they were written as a path); heading, alias and embed marks stay. Settings › Links: fix automatically with Undo (default), offer afterwards ("Fix links"), or leave alone | Matches Obsidian's default and gives a choice | `src/notes/link-update.ts`. Moves between spaces: N25–N27 |
| N24 | **Notes and Tasks have an "All spaces" choice in the space picker, remembered per device and per page.** Notes: each kept space is a top-level folder of the tree, search and the quick switcher cover every space and label hits with their space. Tasks: every space's tasks in List, Board and Table, each with its space name; the picker is the space filter. New notes and tasks go to the open note's space, else the last used space (Tasks has a "Space for the new task" picker while all spaces show). Moving between spaces stays out of scope | Owner request B14; same default as Timer (X19, X20) but opt-in, so the one-space layout stays unchanged | `useAllSpaces`, `SpacePicker`, `useNoteIndexes`, `searchSpaces` |
| N25 | **A note moves to another space by copy.** It is copied into the other space's document (new id, same text) and soft-deleted in the old one; no stub is left. A folder moves the same way, empty folders included. Undo is the reverse move, so the note gets another new id | A note is a record in its space's document and cannot change documents | `moveToSpace` in `src/notes/space-move.ts`; "Move to…" has a Space picker |
| N26 | **A link names a space as `[[Space name:path]]`** (heading, alias and embed marks as before). `:` is not allowed in note paths, so the prefix is unambiguous; the longest matching known space name wins. After a move: links in the old space to the note become `[[New:…]]`; links in the note to notes left behind become `[[Old:…]]`, to notes that moved with it plain; `[[Old:…]]` links in the new space become plain. Same Settings › Links choice as N23 (auto with Undo, Fix links, off). Clicking a prefixed link opens the note in that space | Keeps links working without a second link format for the common case | `planSpaceMove`, `parseSpaceTarget` in `src/notes/space-move.ts` |
| N27 | **Not handled by a space move:** links from a third space, backlinks across spaces, and a time entry's `task_id` (it keeps the old id, so the entry no longer shows its task). An existing unprefixed link in the new space is not checked against the arriving note | Out of scope for #59 | Follow-up if it matters in the trial |
| N28 | **Property values are chosen with native controls.** `status` and `priority` are selects (usual values `open`, `in-progress`, `done`; `none`, `low`, `normal`, `high`, plus any value other notes already use); `due`, `scheduled`, `start`, `end`, `completedDate` get a date input, and a time input once there is a date; tags, `projects` and `contexts` get a "Choose…" list of values already used in the space beside the typed entry. Written values keep TaskNotes' forms (`YYYY-MM-DD`, `YYYY-MM-DDTHH:mm`); values with a zone or free text stay a text field | Native pickers work on a phone; the formats stay readable by TaskNotes and Obsidian | `src/notes/property-choices.ts`, `Properties.tsx` |
| N29 | **Notes and tasks are selected like time entries** (shared `src/app/selection.ts`): a checkbox per row after "Select", Ctrl/Cmd click, Shift click for a range in the order shown, touch long press. It works in the Notes tree, search results, and the Tasks list, board and table, also in "All spaces" (each note is edited in its own space). Folders are not selectable | One selection model for the app; moving a folder already has its own action |
| N30 | **Bulk actions: tags (add or remove), move to a folder, move to another space, delete; on the Tasks page also status, priority, due or scheduled date (set, clear, or shift by days).** Each is one transaction per space with the `bulk-edit` origin, one Undo, a count in the notice. A move to a folder or space plans note after note, so two notes with one name do not both go (the second is skipped and counted), and links follow under Settings › Links as for one note (N23, N26); with "offer", a "Fix links" notice follows. Marking Done also sets `completedDate` (N3). The `task` tag is never touched by tag actions on the Tags page; here adding or removing `task` by hand is allowed | Same rules as a single note, applied to many | `src/notes/bulk-edit.ts`, `NoteBulk.tsx` |
| N31 | **Outline** lists a note's ATX headings (front matter and code skipped) in the note's footer; a click puts the cursor at the heading and scrolls to it | Obsidian's outline pane, without a side pane | `src/notes/outline.ts`, `GOTO_EVENT` in `NoteEditor.tsx` |
| N32 | **Unlinked mentions** are notes whose text contains this note's title as a whole word, any case, with no link to it; code and existing `[[links]]` are not searched; titles under 3 characters are ignored. Listed only, no "Link" button yet; same space only | Cheap and predictable; a one-click link needs an edit of another note's text | `src/notes/mentions.ts` |
| N33 | **Bookmarks are notes starred from the note menu**, kept in the account document's `bookmarks` map (`<spaceId>:<noteId>` → true/false) so they follow the account's devices. The Bookmarks list tops the Notes sidebar (spaces on show only). A note moved to another space gets a new id (N25) and loses its bookmark | Bookmarks belong to the person, not to one space's shared document | `src/notes/bookmarks.ts` |
| N34 | **Weekly and monthly notes work like the daily note**: own folder, name format and template (Settings, defaults `Weekly/GGGG-[W]WW`, `Monthly/YYYY-MM`, `Templates/Weekly`, `Templates/Monthly`), opened from a calendar menu in the Notes toolbar. Weeks are ISO 8601 (Monday first, `WW` and `GGGG` tokens) regardless of the week-start setting, so a file name is the same on every device | A name must not depend on a per-person setting | `openPeriodNote` in `daily.ts`, `readPeriodic` in `src/core/templates.ts` |
| N35 | **A task's checklist progress is its `- [ ]` / `- [x]` lines in the note body ("2 of 5"); fenced code is skipped.** Shown on list and board cards; the front matter is not touched | The note text stays the single source of truth (no stored counter to drift) | `checklistProgress` in `tasks.ts` |
| N36 | **"Make this a task" (Ctrl+Shift+T on a checkbox line) creates `Tasks/<text>.md` with `projects: [[<this note>]]`, status `done` if the box was ticked, and turns the line text into `[[<text>]]`** | The current note acts as the project, so the group view shows the steps; the link keeps the line readable and the box in step with the checklist count | `makeTask` in `editor-commands.ts` |
| N37 | **Tasks › Projects groups tasks by `projects` (wikilink or plain name; alias, folder and heading dropped, case-insensitive); a task with several projects is in each; the rest sit under "No project". Progress is finished tasks of all tasks in the group.** Each named group has a field that adds a task with that project | TaskNotes' `projects` field, no new data | `groupByProject`, `TaskProjects` |
| N38 | **Recurrence follows TaskNotes: `recurrence` (RRULE text, with or without `DTSTART`), `scheduled` = next open occurrence, `complete_instances`, `skipped_instances`.** Supported: `FREQ` DAILY/WEEKLY/MONTHLY/YEARLY, `INTERVAL`, `BYDAY` (weekly), `BYMONTHDAY` (incl. -1), `UNTIL`. Anything else (`COUNT`, `BYSETPOS`, `-1FR`, …) is kept untouched and finishing such a task just marks it done. No `recurrence_anchor` or materialised occurrence notes | Our own ~100-line stepper instead of a dependency (goals: few deps); the unsupported parts are rare in a personal list | `src/notes/recurrence.ts` |
| N39 | **Finishing a repeating task (checkbox, board move to done) adds the scheduled day (else due, else today) to `complete_instances`, moves `scheduled` to the next open day and keeps `status: open`; `due` is not moved.** Bulk "status → done" does not do this yet. Quick add: `repeat:daily\|weekly\|monthly\|yearly` writes `DTSTART:<due or today>` and `scheduled` | TaskNotes' default behaviour (due offset option left out) | `recurringCompletion` in `tasks.ts` |
| N40 | **Agenda (Tasks › Agenda): overdue open tasks, then each day with items over today + 14 days, from `due` and `scheduled`; a task with both appears for each; repeating tasks list every occurrence in the window, later ones greyed and without a checkbox.** Finished tasks are hidden; no calendar grid, no reminders | Issue scope: today and upcoming at a glance | `buildAgenda` in `src/notes/agenda.ts` |
| N41 | **Archiving a task adds the tag `archived` (TaskNotes' default); archived tasks are hidden from List, Board, Agenda and Projects and shown by "Show archived", where each has Restore.** "Archive finished" archives every finished task on view. The table still lists them. Nothing is deleted | Reversible, and Obsidian with TaskNotes sees the same archive | `archiveChanges` in `tasks.ts` |
| N42 | **Built-in rules, switchable in Settings › Task rules (account-wide, `task_rule_<id>` in the account `settings` map): completed date on Done (on by default, N3); open → In progress when the timer starts from a task (off); archive 30 days after completion (off, runs when Tasks opens).** No user-defined rules or scripts | Owner wanted a few fixed rules, no scripts (goals) | `src/notes/task-rules.ts`, `TaskRulesCard.tsx` |
| N43 | **Board per project:** a "Board for" picker (all, one project, no project) filters the board by `projects`; a project is a named group as in N37. Not a separate saved board | Same data, no new document | `TaskBoard` |
| N44 | **Tasks page cleanup (#135):** list filters (Status, Due, Context) and the board's project filter sit in the page header (`PageHeader` `filters` slot; one full-width row on phones). The status pill shows only for statuses other than `open`; statuses read as "In progress", "Done" (`statusLabel`; stored values unchanged). Board cards drop the ← → buttons: play and a "…" menu ("Move to <column>", Archive or Restore) appear on hover, always on touch; drag and drop stays | The first screen held the tasks, not five rows of controls; "open" on every row said nothing | `ListFilters`, `BoardFilter`, `TaskCard` in `TasksView.tsx`; `statusLabel` in `tasks.ts` |
| N45 | **Universal search (#149):** `src/app/views/SearchDialog.tsx` ranks items that modules register as search sources (`registerSearchSource`: notes and tasks, time entries, projects and clients, tags), so the app never imports a module. Searches titles, paths, aliases, text and front matter, entry descriptions, project and client names, tag names and space names; words in any order, `"phrases"`, `#tag` (`queryTerms`, now in `src/core/search.ts`). Items are collected when the dialog opens and again (150 ms debounce) when a document changes; no stored index. Not searched: history versions, other people's spaces | Plain scans are fast enough for a few thousand notes; a stored index is more state to keep in step |
| N-166a | **Files are content-addressed (SHA-256), stored per unit (a space; later a single-note share) in IndexedDB `app-blobs-<unitId>` outside Yjs; an `attachments` map in the unit's document indexes them (name, size, type, width, height, created_at, deleted).** An absent map reads as empty, so no migration (F39) | Yjs history never shrinks; the unit boundary already decides who holds data | `src/core/blobs/` |
| N-166b | **Any file type, 10 MB per file, 1 GB per space; notice at 80% of the space or of the browser quota; over a cap the add is refused with the sizes** | Owner decisions 1 and 7 of #166 | `limits.ts`, `addAttachment` |
| N-166c | **Inline display only for bytes that sniff as PNG, JPEG, WebP or GIF; everything else (SVG and HTML included) is a chip with Download and is stored as `application/octet-stream`. `img-src` gains `blob:` on the app rule only** | A blob URL has the app's origin, so scriptable types must never render | `sniff.ts`, `public/_headers`, `scripts/e2e/files.mjs` |
| N-166d | **Originals are kept. An image over 2560 px gets a display copy made on demand and cached on this device only. "Shrink large photos" is a device-only option (`localStorage` `image_downscale`, Manage › Notes › Files), off by default** | No silent loss of the original; a device option avoids a shared-settings change in slice 1 | `images.ts`, `host.ts`, `FilesCard.tsx` |
| N-166e | **Location data is warned about (JPEG, PNG, WebP, HEIC EXIF GPS; MP4/MOV `©xyz`), never stripped** | Stripping is another tool's job; the user decides (owner decision 8) | `hasLocationData` |
| N-166f | **Name clash: ` 2` suffix before the extension on the later add; identical bytes give one entry; a pasted screenshot is named `Pasted image YYYYMMDD-HHMMSS.ext`; characters that break `![[ ]]` become `-`** | Readable names in the mirror (owner decision 9) | `uniqueFileName`, `cleanFileName` |
| N-269 | Files in the mirror folder and the Obsidian vault: `<Space>/attachments/<name>`, flat, any type. A file new there enters the store and index (10 MB cap, ` 2` suffix on a clash, renamed on disk too); a file deleted there is deleted (index entry and bytes), and the other way round; arrivals from sync are written when missing. Files are tracked by path in `MirrorState.files` (absent in older state = empty) | Owner decisions 4, 6, 9 of #166: one folder per space, deletes are deletes for everyone |
| N-269b | A file edited outside keeps its name with new content: the old index entry is deleted, the new bytes are added. Supersedes "the old entry stays" in the design note | Names are unique, so two live entries cannot share the name the folder shows |
| N-269c | In Obsidian, files pasted elsewhere in a space folder are copied into `attachments/` (the original stays, is never deleted by Yak); the plugin ignores "Default location for new attachments" and says so in its settings. `.md` files inside `attachments/` are files, not notes | Obsidian resolves `![[name]]` vault-wide, so the stray still works; one rule for the folder |
| N-271 | Unused files (#166 slice 5): Manage › Notes lists, per space, the files no live note names with `[[name]]` or `![[name]]` (alias, width and heading ignored, case-insensitive; code blocks not masked, so doubtful ones count as used), biggest first, with the total. A soft-deleted note is no reference; note history is not. **Delete** (asks "Delete for everyone") marks the index entry `deleted`; every device drops the bytes when it sees the mark (`startFileSweep`), so a delete is a delete for everyone and a backup is the way back (B-270b). Nothing deletes a file by itself: removing its last link keeps it. A file deleted in the mirror folder is a delete too (N-269) and its bytes go the same way | Owner decision 4 of #166: nothing disappears behind the user's back, the user decides. Dropping bytes where the mark arrives keeps devices from holding files the index no longer names | `src/core/blobs/unused.ts`, `src/app/file-sweep.ts`, `src/settings/UnusedFiles.tsx` |
| N-272 | Moving a note to another space copies the files it names (owner, #166 slice 6): each `![[name]]` or `[[name]]` that is a file of the source adds the index entry to the target (same hash, so no second copy of the bytes; the entry keeps its type, size, pieces and date) and copies the bytes this device holds. A file the device does not hold is indexed and fetched from peers as usual. A name held by other bytes in the target gets the ` 2` suffix (N-166f) and the link is rewritten; the same bytes already there are reused under their name. The source keeps its files, so Undo and other notes there still work; the unused-files list (N-271) cleans up later. Single-note shares are gone (S-259b), so "share a note" is this move into a space of its own | Files belong to the space that holds the note; nothing deleted by a move | `src/core/blobs/copy.ts`, `copyFiles` in `src/notes/space-move.ts` |
| N-pre1 | **Shortcuts (pre-share fix):** "Find a note" is Ctrl+O only; Ctrl+P is left to the browser's print. "Make task" on a checkbox line is Ctrl+Shift+Enter, not Ctrl+Shift+T (the browser's reopen-closed-tab, which never reaches the page). This changes NE16 and N36 | A page cannot intercept reserved browser shortcuts, and users expect Ctrl+P to print. Ctrl+Shift+Enter is free in browsers and the editor, and sits beside Ctrl+Enter (tick a task). Ctrl+Alt+letter was avoided: AltGr on some layouts, and Ctrl+Alt+T opens a terminal on Linux | `notes.find` in `src/notes/index.ts`; `Mod-Shift-Enter` in `src/notes/editor.ts`; `SHORTCUTS` in `editor-commands.ts` |
| N-11 | Moving a note to another space also copies files named by Markdown links and images (`![](x.png)`, `[t](x.pdf)`), found with the same parsing as `referencedNames`. If a file is renamed there, the whole link target becomes the new name, URL-encoded (a folder prefix, `#` and `?` parts are dropped) (#11) | Files are found by last name segment, so the path adds nothing; the move should not leave broken images | `copyFiles` in `src/notes/space-move.ts`; `markdownTargets` in `src/core/blobs/unused.ts` |
