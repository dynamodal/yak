# Decisions: Obsidian

Reference: `../design/external-editors.md` (routes not built), `../../obsidian/README.md`. O3 and the spike's read-only scope are superseded by O8.

| # | Decision | Why |
| --- | --- | --- |
| O1 | The spike declares the few Obsidian types it uses (`obsidian/src/obsidian.d.ts`) instead of depending on the `obsidian` package | The package pins exact CodeMirror versions that clash with the app's; revisit with the real plugin (#64) |
| O2 | The spike reuses `src/sync` unchanged and is bundled from this repo (`npm run build:obsidian`, Vite library build, CommonJS) | One protocol, one implementation; a second client would drift |
| O3 | The spike accepts only `account/*` documents and holds them in memory | It is not in any space's `keeps`, so no notes reach it; nothing to clean up afterwards |
| O4 | The pairing is stored in `localStorage` under a key with the vault name | Desktop Obsidian shares `localStorage` across vaults |
| O5 | The connection log is saved to the plugin's data every 15 s and on visibility changes | The question is what happens in the background; the log has to survive it |
| O6 | Android Obsidian is assumed to work, untested; the spike counts as passed on desktop | Owner, 2026-10-17: a phone install costs more than it tells. Test on the phone with the first real plugin (#64); the risks (background links, WebRTC in the mobile webview) stay open until then |
| O7 | (Superseded by O20.) The plugin id was `punchdeck`, name "Punchdeck", version from `obsidian/manifest.json` | The id is the folder in users' vaults; only the owner has installed it. The rename (#92) must decide the id before anyone else does |
| O8 | The plugin is a device with its own `keeps`; it keeps nothing until the owner ticks spaces on the Devices page, and never opens a space's private part | Same rule as every device; time entries are not Markdown |
| O9 | Documents are saved as files in the plugin folder (`docs/`), the whole state after 1 s without edits | An empty copy at start would read every file as deleted. Files, because Obsidian has no IndexedDB guarantee on mobile |
| O10 | The engine and `MirrorService` run unchanged; the vault is a `MirrorFs` rooted at `<root>/` and the vault rules run before each pass | One engine for every route; rules are vault-specific and stay in `obsidian/` |
| O11 | One root folder (default `Yak`, a setting); changing it starts from an empty mirror state and deletes nothing | Same as M12; nothing outside the root is read or written |
| O12 | A renamed space folder is renamed back when exactly one unknown folder holds files at the paths the missing folder had; otherwise the space is held | A rename is not a space rename; a guess on weaker evidence could move the wrong folder |
| O13 | A deleted space folder holds the space (left out of the pass) until the owner restores the folder or stops keeping the space here | The engine would read every file as deleted and delete the notes; notes are never deleted for a folder |
| O14 | Links are translated in `VaultFs`: `[[Space:path]]` to `[[Yak/<folder>/path\|title]]` on write, back on read; plain links to a name that exists in two spaces get the folder | Obsidian resolves vault-wide, the app per space. Files nobody edited are rewritten when the set of kept spaces or note names changes (`relink.ts`) |
| O15 | `SyncService` takes `realAddresses: false`, so the plugin never asks for the camera | There is no camera prompt in Obsidian; connections use the addresses the webview gives |
| O16 | Deletes go to the vault's trash (`fileManager.trashFile`), renames use `vault.rename` | The user's trash setting decides; `vault.rename` leaves link rewriting to the engine, so Obsidian and the engine do not both edit links |
| O17 | `getAllLoadedFiles` and `trashFile` set `minAppVersion` to 1.6.6 | Not tested against older versions |
| O18 | Releases come from a tag workflow (`release-obsidian.yml`), not from the owner's machine; the script only tags a clean, up-to-date main | The attached files are built from reviewed code; the workflow fails if tag and manifest version differ |
| O19 | Install and update through BRAT, no Community plugins listing yet | Updates without a store review; the listing needs a public repo and a plugin-only `manifest.json` at the root, revisit when the plugin is for others |
| O20 | The plugin id is `yak-sync`, name "Yak Sync", and the pairing key `yak-sync-<vault>`, root folder default `Yak`; supersedes O7 and the key name in O4 | Searchable in the plugin list next to the app name; the id is the vault folder, so it is fixed before anyone else installs (owner, 2026-10-18, #92) |
| O221 | The plugin says where the sync code (`localStorage`) and documents (`.obsidian/plugins/yak-sync/`, unencrypted in vault sync) live, in the README and at the top of its settings; setting "Keep documents in the vault" defaults to on, off keeps them in IndexedDB | On keeps today's behaviour for alpha testers (F39) and survives a cleared webview database; off is for vaults on a shared sync service. Switching imports the old files once and deletes them only at a later start, when IndexedDB already holds the document. Encrypting the vault copy is out of scope |
| O-257 | The plugin is a device with keys (S-76p, owner, #257): keys in protected browser storage (non-extractable, IndexedDB, named by the vault's device id) when available, else in `data.json`; the settings tab says which and shows the vault's fingerprint. It pins the account key as the app does, signs handshakes, and joins a keys-required account by one-time invite (the comparison code in a notice). Version 0.2.0; until a vault runs it, Devices lists it as not ready and the switch waits | Same rules as any device; honest about the weaker storage |
| O-91 | Never resolve a promise with an Obsidian component (`Setting`, `Modal`, `Notice`): a `.then` or `async` callback returns nothing (block body). The e2e stand-in's `Setting` has `then`, as in Obsidian 1.14 | Obsidian 1.14's `Setting` is a thenable; resolving with it loops forever on the microtask queue and freezes Obsidian (#91) |
