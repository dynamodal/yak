# Settings: decisions to review

Choices made while building `src/settings/` that the owner may want to change.
Each row says what was decided, why, and how to change it.

| Decision | Why | How to change it |
| --- | --- | --- |
| The Settings page is the only place to change the hours format; the selectors on Timer, Entries and Reports were removed | One home for the setting, as asked in owner question Q9. Each page still reads the setting and re-renders when it changes | Re-add a selector with `useSettings()` from `src/app/hooks.ts` |
| Shared settings are read and written through `src/core/settings.ts` and the `useSettings()` hook | Modules stopped reading the `settings` map ad hoc. Time reads it through the hook; reports read it through `readSettings` because they use the document directly | Add a key to `SharedSettings`, `readSettings` and `parseConfig` |
| The stored hours format value is `hm`; the older `h:mm` (written by the reports selector) still reads as `hm` | The architecture and the time module use `hm`. Documents written by an earlier build stay valid | `parseHoursFormat` in `src/core/settings.ts` |
| Theme is device-only, kept in `localStorage` under `theme` and applied as `data-theme` on `<html>`; no value follows the system | A theme is a per-screen taste, so it never goes into a synced document. Without the attribute the `prefers-color-scheme` rules apply, so the default is unchanged | `src/settings/theme.ts` and the `color-scheme` rules at the top of `src/app/theme/tokens.css` |
| The theme is applied when the settings module loads, not by an inline script | The Content-Security-Policy forbids inline scripts. There can be a brief flash of the system theme on load | Move the call earlier in `src/app/main.tsx` |
| The settings config file is JSON with `kind`, `version` and the shared settings only | Small and checkable. Device-only settings (theme, signaling server, backup folder) stay on the device | `settingsToConfig` and `parseConfig` in `src/core/settings.ts` (removed with the buttons, F-323) |
| Importing a settings file applies the known keys and ignores unknown ones; a known key with a bad value rejects the whole file | A newer version of the app can add keys without breaking older ones, while a corrupted value never half-applies | `parseConfig` |
| Devices and Backups settings are linked, not repeated | Their controls need their own services (pairing, folder handle) and have one home each | Move a control into Settings later |
| The app version comes from `package.json` through a Vite `define` (`__APP_VERSION__`) | Available with no new dependency. It reads `development` when the define is missing | `vite.config.ts` |
| Settings is four Manage sections (#135): **General** (week start, hours format, history warnings, theme, export and import, about), **Spaces**, **Notes** (links, task rules, daily, weekly and monthly notes as one table) and **Shortcuts** (a compact table, quiet Change and Reset). Routes `#/settings`, `#/manage/spaces`, `#/manage/note-settings`, `#/manage/shortcuts`; the palette says "Go to Settings" and "Go to Note settings" (`commandTitle`) | The one page was 3700 px tall at 1280 px; each section now fits a screen and the Manage list says where things are | `src/settings/index.ts`, `SectionViews.tsx`, `PeriodicNotesTable` in `DailyCard.tsx` |
| F-309 | **Security** is Settings' own page for the passphrase (set, confirm, unlock, forget), with "What your passphrase protects"; Backup & restore, Sharing and Devices link to it ("Set a passphrase →"). Every passphrase field has a **Show** switch (`PassphraseInput`). Typed passphrases are refused under 20 characters and warned under 28 ("four or more random words is best") with a live hint; suggested phrases are redrawn until 28+. Unlocking never checks length, so older shorter passphrases keep working; the page shows a note when the one typed last was short | The passphrase seals the account key, so it approves devices, removals and shares, not just backups; one place and a longer minimum fit that. No library or network; no way to lock anyone out. A change-passphrase flow does not exist yet | `src/backup/SecurityView.tsx`, `src/app/ui/PassphraseInput.tsx`, `src/core/passphrase.ts` |
| F-309b | **Features** (Settings › Features) hides Notes, Tasks, Reports, Mirror and Import **per device**: the list `hidden_modules` in `localStorage`, absent means all on. One filter in the registry (`allViews`, `allCommands`, `allSearchSources`, in `src/app/features.ts`) covers nav, Settings pages, palette, shortcuts and search; a hidden page's route goes to the timer. Notes hidden also hides Tasks. Timer, Backup & restore, Devices and the sync status are never hidden. Hide only, no data touched, no migration (F39). Welcome's presets set the list: Time tracker (Notes, Tasks hidden), Time, notes and tasks (none) | A time-only device still receives and stores notes through sync and backups; only pages hide. Per device (owner's answer, #300) needs no sync of the choice. The timer has no task picker yet, so nothing to hide there | `src/app/features.ts`, `src/settings/FeaturesView.tsx`, `src/app/Welcome.tsx` |
| F-313 | **Spaces and Sharing split (#313, #300); superseded by F-326.** Settings › Spaces holds no sharing, no raw id and no "Kept by" (keeping is chosen on Devices); a space shared with you offers "Leave share", never "Remove". Settings › Sharing (`SharingView`, lazy) lists every space with a two-step checklist (passphrase, then a link); the link folds away once every asker is answered | One place, one page per job; the old per-card copies repeated the same text | `src/settings/SharingView.tsx`, `SpacesCard.tsx` |
| F-323 | **Generated passphrases join words with hyphens** (`cobalt-fern-ledger-mango-quiet`), not spaces. **Export settings and Import settings are dropped** from Settings | Spaces confuse people (owner, 2026-10-24); typed passphrases are unchanged, so existing ones keep working. Backups contain `settings.json` and sync carries the settings, so the buttons repeated them and "Import settings" was confused with Import | `src/core/passphrase.ts`; restore the buttons from git history |
| F-324 | **One passphrase sheet, opened by the action that needs it**; creating a passphrase also gives this device keys (`requireKeys([me])`) without starting pairing, so a single device can share. Unlock lasts 5 minutes after the last use | Replaces four prompt components and the Security page detour; one-device sharing was a dead end (owner: a user must be able to share with one device). A sliding window stops repeat prompts while a lost phone still locks within minutes | `docs/architecture.md`; `UNLOCK_MS` in `src/app/unlock-window.ts` |
| F-324b | **Passphrase sheet details (#324).** `withKey({ verb, run, unlock?, fresh? })` (`src/app/key-prompt.ts`) runs the action at once when the key is unlocked and the device is set up, else opens the lazy `PassphraseSheet`; a throw stays in the sheet. After creating, a device that syncs with nothing (`!paired`) runs `requireKeys([me])`; a paired older account keeps its Devices banner (approving only this device would cut the others off). Each use of the account key restarts the 5 minutes (`UnlockWindow.use`); background refreshes only look (`peek`). Restore asks for a backup's passphrase in the same sheet (`askBackupPassphrase`) only when this device's key does not open the folder. A share link opened before setup is kept 15 minutes in `localStorage` (`pending-share`, device-only, no migration) | One component for 11 prompts; sliding unlock stops repeat prompts without lengthening the idle lock | `src/app/key-prompt.ts`, `src/app/views/PassphraseSheet.tsx`, `src/app/unlock-window.ts`, `src/app/pending-share.ts` |
| F-325 | **Organize page** for projects, clients, tags and task values, owned by no tab; reached from "Edit…" in every picker, the palette and one Settings row. Note settings and Mirror move behind a ⚙ on Notes; Shortcuts move into Help | These labels are used across Timer, Notes and Tasks, so neither Reports nor Settings owns them (owner, 2026-10-24). Timer and task projects stay two lists until #327 | `docs/architecture.md` (Pages) |
| F-326 | **Settings is one scrolling page with no sub-menu:** a Your data table (spaces × devices, keeps in the cells, shares per row, status lines below), Preferences, About & help. Supersedes the F-313 split of Spaces and Sharing and the F-304 "last page used" landing | Six pages described one thing; a grouped home with drill-in (close to F37) kept every concept and added taps. Rejected: a "Data" tab with preferences behind a header ⚙ (crowded header) | `docs/architecture.md` (Pages) |
| F-326b | **Settings page details (#326).** Columns are this device first, then the account's other devices that are not removed or left; an undecided cell is an indeterminate checkbox, and the "Keep / Not on this device" notice (`UndecidedNotice`) shows above the table and on a device page. Status lines are one row each (dot, text, link) and a registry (`registerDataLine`): Backup and Import add theirs, the page owns Passphrase and Sync, and a device that never paired with no passphrase shows neither. "Share…" opens a sheet around the existing `SharePanel`; the same panel is on the space's page. The passphrase's explanation, "Forget on this device" and the account-key card moved into a section of Backup & restore (no Security page). A space's page links to Note settings for files; Import is a link under the table. The old `app-manage-section` key is dropped unread (UI-only, no migration, F39 unaffected). Detail views: a device (`#/settings/devices[/<id>\|/add]`), a space (`#/settings/space/<id>`), Backup & restore, Import. Rejected (design note, deleted when this shipped): a UI library or CSS framework (no bundle room), a Settings sheet over the page (F21), a sixth tab (F14). Still open: #327 and #328 | The page names no feature module (hard rule); a registry matches `registerSection` (F-325b). Passphrase upkeep is about backups and the account key, so it sits with Backup & restore | `src/settings/DataCard.tsx`, `DataLines.tsx`, `SpaceView.tsx`, `src/app/data-lines.ts`, `src/backup/PassphraseSection.tsx` |
| F-325b | **Organize and note settings are pages assembled from registered sections** (`registerSection`, `src/app/sections.ts`): Task values (notes) and Mirror (mirror) add themselves, so no feature imports another. Mirror always shows; without folder access it reads "Not available in this browser: it needs folder access" and names no browser | The shell may not import feature modules (hard rule); a registry matches `tag-sources` | `src/app/views/Sections.tsx`, `src/mirror/index.ts` |
| F-334 | **Other accounts list, space page and account page (#334).** Settings home keeps the spaces × devices table (shares only as chips: "Studio", "from Alice", "link open") and adds an Other accounts list under it with the edit-and-delete warning and "+ Share with an account" (pick a space, then the normal link flow). A space's page (`#/settings/space/<id>`) holds Kept on (each device, ticks, last seen) and Shared with (accounts with fingerprint, since, End…/Leave…, an open link with time left and Cancel link, "+ Share <space> with an account"). An account's page (`#/settings/account/<fp>`, lazy) shows the full fingerprint, your label with Rename, "You share with X" (End…, "+ Share another space" offering only spaces not yet shared with it) and "X shares with you" (Leave…). The per-row Share… is gone | An account, not a column, is the unit of trust: a tick cannot tell keeping data on a device from giving another account edit and delete rights with no recall (owner, 2026-10-25). Rejected: accounts as table columns. Say "account", never "person" | `docs/architecture.md` (Pages, sharing between accounts) |
| F-334b | **Details (#334).** The label for an account is stored in the account document (`settings` map, `account_label:<fp>`), so all your devices agree; the other account never sees it, and an absent key reads as the name it chose, so no migration (F39). When the account that asks through that link has a different fingerprint than the page's, the owner's screen says so plainly before Approve; it does not block.
