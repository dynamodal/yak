# Decisions: sync, devices, accounts

Reference: `../sync.md`.

| # | Decision | Why |
| --- | --- | --- |
| S1 | Sync code pairs a device to the whole account; every device links to every other (mesh, cap 8); edits relay | No single point of failure; 8 is far above need |
| S2 | One shared key for the account; per-device keys later | Simple for one person's devices; required before sharing with others |
| S3 | The site's own relay (`/signal` on the Worker) is the default; ntfy.sh selectable | Measured: pairing 0.5 s, reconnect 0.3 s; one origin |
| S4 | Relay room cap: evict the oldest socket | A laptop that slept is not locked out by its own stale socket |
| S5 | `/signal` checks the browser's `Origin`, limits new connections per address, and caps each room's relay data per day (S53–S55) | Replaces "no limits yet": the relay must not be a free data pipe once the app is public |
| S6 | Automatic signaling only announces; forced triggers offer; background back-off to 15 min | An asleep phone made the laptop replace offers on every edit |
| S7 | Account document `account/<id>`; space ids random (24 hex); names unique per account, renameable | Names never merge spaces |
| S8 | Each space has a shared part and a private part (`space/<id>/private`: time entries, rates) | Time and rates never go to other accounts |
| S9 | Which spaces a device keeps is one choice per device (`keeps`), explicit; a new device keeps nothing until chosen | Closes the race where data reached a newly added device before the owner chose |
| S10 | A space created on another device is undecided here until chosen | Opt-in per device |
| S11 | Joining reloads once; a joining device's spaces with data are kept as "Personal (<device name>)" | Nothing lost, nothing merged by accident |
| S12 | Restoring another account's backup on a device not syncing adopts that account; restored spaces are kept | Wiped-browser recovery |
| S13 | Remove is stored in the account document; leaving marks `left`; erase on leaving is offered per space, off by default | Every device agrees on the list |
| S14 | Changing the code reaches linked devices over a control frame | A new code used to cut every other device off |
| S15 | Two status levels: this device (chip), each other device (row) | "Not connected" was ambiguous |
| S16 | Words: "sync code", "account" | Owner's preference |
| S17 | An entry's space follows its project; one tag list per space. Moving a project to another space moves its entries by default (owner, 2026-10-19; see `time.md`) | Owner, 2026-10-16 |
| S18 | Encrypted backups: one passphrase per account | Owner, 2026-10-16 |
| S19 | Accept the shared-key trust model for now, with a clear warning; device keys later | Owner, 2026-10-16 |
| S20 | Turning a space off for a device does not delete it there | Remote deletion needs device identities |
| S21 | Reset this device's data (Devices page): one space or everything; erased at the next start, like leave-with-erase | Databases cannot be deleted while open |
| S22 | A reset needs a safety backup file saved first, and is offered only while another device is linked or a backup exists; refused for a space no other device keeps and no backup covers | Nothing may be lost silently |
| S23 | "Changes only here" = Yjs operations the linked devices' last announced state vectors lack (smallest over devices), shown as "about n" | Needs no new protocol message; a size, not an exact edit count |
| S24 | Reset of everything also erases the account document and forgets the sync code; the device keeps its id and rejoins with the code | The account document is part of the drifted copy |
| S25 | The history log is kept on reset unless chosen | It is the record of what happened before the drift |
| S26 | Spaces are created, archived and removed in Settings › Spaces; the creating device keeps a new space, others see it undecided (S10) | Vault folders map to spaces (#64) |
| S27 | Archive = `<id>:archived` in the account document: hidden from pickers and lists, still kept and synced, reversible | Tidy lists without risking data |
| S28 | Remove = `<id>:deleted`: every device stops keeping and syncing it; data stays in backups and history; the name is free again | Same record `readSpaces` already honoured |
| S29 | Removal confirms with note and entry counts (or says this device cannot count); erasing the local copy is an opt-in tick, this device only | Nothing lost silently; no remote deletion (S20) |
| S30 | The last active space cannot be archived or removed | A device with no space shows only Devices |
| S31 | Every device's name is editable from every device in the account; concurrent renames resolve by last write | Names are plain per-field values (`setDeviceName`); a lost or unreachable device can still be named from another |
| S32 | A device with no account spaces and no sync code shows a welcome (join, start fresh, restore) and creates no space until one is chosen; this replaces the automatic Personal and Work | Joining then inherits exactly the account's spaces; no "Personal (<device>)" duplicates for fresh devices. `?test` pages keep the two defaults unless they add `?welcome` |
| S33 | Start fresh makes the account's first space with a chosen name (default Personal); the device keeps it | More spaces are added in Settings |
| S34 | S11 still applies to a device that already holds data when it joins | Nothing lost, nothing merged by accident |
| S35 | Each device copies its sync event log into synced log documents: `account/<id>/log` (pairing, links, signaling; all devices) and `space/<id>/log` (events about that space; only devices that keep it) | Debug across devices from any one; the space rule reuses the keeps filter, so a space log never reaches a device that does not keep the space |
| S36 | Lines are `{at, device, kind, detail}` under fresh UUID keys; each device deletes only its own lines older than 7 days or beyond 3000 per document | Bounded size without a coordinator; the one place records are hard-deleted, because the log is not user data |
| S37 | Always on during alpha; becomes opt-in before release to others (checklist in #92) | Owner decision 2026-10-17; the log has connection addresses, so it stays inside the account |
| S38 | Log documents are left out of backups and history, and erased with their space or account on leave and reset | They are diagnostics, not data worth restoring |
| S39 | Devices page › Logs from all devices: lines merged by time, filter by device, Copy report | Same place as the local connection log |
| S40 | `PeerLink` splits a message larger than the channel allows (`sctp.maxMessageSize`, at most 64 KiB per piece) into ordered pieces and joins them on receipt; small messages go unchanged; sends wait while more than 1 MiB is buffered | A full-state catch-up outgrew 256 KiB and `send` threw, so a device stayed connected but never caught up; unchanged small messages keep older builds working |
| S41 | One tab per browser profile runs sync (Web Lock per pairing storage key); other tabs sync with it over a `BroadcastChannel` with `DocMux`; a tab takes over when the leader closes, does not answer within 2 s, or the person acts on sync there | Several tabs with one device id each answered the same offer, so the other device often linked to a background tab and the visible one never connected |
| S42 | The browser profile (origin) is the trust boundary on a device; cross-tab messages are not encrypted | A `BroadcastChannel` reaches only same-origin pages of the same profile, which can already read IndexedDB and the sync code. Several accounts on one device later get one lock and channel each |
| S43 | Sync notices (first slice): path conflicts, timers stopped by the one-timer rule, bulk changes from another device; listed on Devices, a dot on the sync chip | Owner request B20 (#72); concurrent edits of one field (Keep mine / Keep theirs) is the second slice |
| S44 | Notices live on this device only (`core/notices.ts`, localStorage), each key added once and never again after dismissal | Each device decides what it has seen; a conflict that stays in the data must not return every start |
| S45 | Concurrent edits of one field (second slice of #72): detected on the device whose value lost, from Yjs map events (the winning item's `origin` is not the item it replaced); `updated_at`, `deleted_at`, `duration` and Y types are ignored | Needs no extra data in documents; the winning side was not surprised |
| S46 | "Keep mine" writes the old value again only while the winner is still in place; "Keep theirs" just dismisses | A later edit is never overwritten by a stale choice |
| S47 | Default ICE servers are `stun:stun.cloudflare.com:3478`, then `stun:stun.l.google.com:19302`; the list is a per-device setting (Devices › STUN servers), not part of the pairing | Without STUN only local addresses were tried, so sync worked on one network only; STUN reveals a public address to its operator but carries no data; people running their own servers set them per device |
| S48 | When no direct link opens within 5 s, data goes through the site's relay, sealed end to end with the account key; the direct attempts continue and win when they open | Mobile carrier NAT and strict firewalls block WebRTC; a relay we already run needs no new hosting |
| S49 | Relay data links are separate sockets, `/signal/<topic>/link/<pair>`, in the same Durable Object; the pair tag is a hash of both device ids | Signaling broadcasts stay unmixed with data; the relay learns no device id; one object per account keeps one place for caps (#170) |
| S50 | Whole message sealed once, then cut into 32 KiB pieces; sends paced under per-socket caps | One AES-GCM per message, any size; the caps stop a catch-up from tripping the Worker's limits |
| S51 | Relay and direct are separate paths of one peer session; `onLinkOpen` fires once per connect, so the document exchange does not restart when the path changes | Switching is invisible to sync; Yjs tolerates the overlap |
| S52 | A device row says "Syncing through the relay" while on it | The owner can tell why sync is slower |
| S53 | `Origin` must be the site itself, Obsidian (`app://obsidian.md`, `capacitor://localhost`, `http://localhost`) or listed in `ALLOWED_ORIGINS`; a missing Origin is refused | Stops other websites and casual scripts; a script can fake the header, so S54 and S55 carry the real protection |
| S54 | At most 60 new connections a minute per address (Cloudflare rate-limit binding `CONNECT_LIMIT`), answered 429 | A device that reconnects with back-off uses a few; a loop does not |
| S55 | A room's relay links carry at most 100 MiB per UTC day (`RELAY_DAY_BYTES`), counted in the room and saved in 64 KiB batches; past it both devices get `{"event":"limit"}` and stay quiet 10 min | Direct sync is unaffected; a normal catch-up is a few MB. Signaling is not capped, so pairing never breaks |
| S56 | The app says "Relay limit reached… direct sync still works" on the Devices page | The owner can tell why changes stopped crossing networks |
| S57 | The relay's budget is counted in estimated Cloudflare requests (1 per call, +1 per accepted socket, 1 per 20 messages), one account-wide counter, default 50 000 a day | On the Free plan requests are the scarce unit and bytes are not billed; one address or many rooms could otherwise spend the whole quota. Owner accepted 50 000 on 2026-10-19 |
| S58 | At 80% of the budget new data links are refused, at 100% all `/signal`; signaling goes last | Pairing and reconnecting must outlive the data fallback; direct sync needs no relay once linked |
| S59 | `RELAY=off` is a kill switch; refusals are JSON with a marker field and `X-Relay-Limit`; `GET /signal/status` answers the same way | A failed WebSocket shows no status, so the app asks a plain request; only our Worker can answer with the marker |
| S60 | The app asks `/signal/status` only while the relay seems broken, at most every 2 minutes, and waits up to 5 minutes between connection attempts after six failures | Every attempt is a Cloudflare request; a broken relay must not be hammered by the devices that need it |
| S61 | The per-address connection limit is 30 a minute, the room byte cap stays as a fairness limit | Devices at one home share an address; the account budget, not these, protects the quota. Refused calls still count, so the docs ask for a Cloudflare WAF rule and usage notifications |
| S62 | Connection limits per address and topic (60 a minute) plus a per-address ceiling (1000), replacing S61's 30 per address; a refused device pauses new sockets 90 s | Several people behind one shared address (a VPN or office network) shared one budget, and a refused device's own retries kept it over the limit (#184) |
| S67 | `GET /signal/<topic>/stats` answers counts for the account's room: devices and data links connected, messages and bytes in the last hour and 24 hours (10-minute buckets in the room's storage), last activity; the Devices page shows "Relay: N devices connected · M messages today" and asks when opened, then once a minute while visible | Helps multi-device testing (#171); the topic is the only secret needed and the room sees no content or device ids, so there is no per-device activity, only the room's; each ask is a counted request (2 in the budget) and is address-limited |
| S65 | Devices › Logs has the switch "Share debug logs between my devices", per device (localStorage), on by default during the alpha; off stops writing and deletes this device's lines from every log document, which sync removes on the other devices | Anyone but the owner can say no to a log with network addresses (#197); ticks the opt-in item of #92 for the device-level choice |
| S66 | A one-time banner on every device says what the log holds (events, device names, addresses; no note or entry contents), that it stays between the person's own devices and lasts 7 days; Got it or Turn it off | People must know before they are asked to trust it; the Privacy help topic (#191) repeats the text |
| S64 | Uncaught errors, unhandled rejections and errors modules pass to `reportError` (`core/errors.ts`) go to the debug log as `error` lines with version, page and four stack lines; a repeat raises `count` on the one line (up to 50 distinct errors remembered); one "Something went wrong" toast per 10 minutes, linking to Report a problem | Reports explain themselves without flooding the log or the person (#196); backup failures log without a toast because the banner shows them |
| S63 | The undecided-spaces notice lists each undecided space with Keep and Not on this device (writes `false`), plus Keep all spaces and None of these; undecided shows as an indeterminate box with "(not decided)" | Amends S10: a deliberate "no" is a decision, so the notice goes away for it (#194) |
| S68 | Operator relay stats use Workers Analytics Engine: one data point per relayed message (room hash, kind `signal`/`link`, size); `GET /signal/admin/stats` behind a bearer `ADMIN_KEY`, querying Cloudflare's SQL API with a token kept as a Worker secret; the binding stays commented out in `wrangler.jsonc` until the owner enables it | Shows active rooms, traffic and how much the relay fallback carries (#173) without a deploy failing on an account that lacks Analytics Engine; Cloudflare's dashboard covers the rest until there are other users |
| S69 | The app side is the unlisted route `#/manage/network`; the admin key is typed once per device and kept in localStorage only | "Hidden until the admin key is entered": nothing in the interface points to it, and the page shows nothing without a key the Worker accepts |
| S217 | Per-address limits: `ADDRESS_LIMIT` 1000 → 120 a minute; `RelayBudget.admit` holds an address (hashed) to 2% of the day's requests and 30 new topics a day, then 429 `reason: address` | One client cycling `yk-<hex>` topics could spend the shared 50 000 a day in about an hour and switch the relay to `links`/`off` for everyone. Costs one budget-object call per accepted socket; fails open if the object is unreachable. Messages on open sockets are not attributed to an address | `DEFAULT_ADDRESS_SHARE`, `DEFAULT_ADDRESS_TOPICS` in `worker/index.ts`; vars `ADDRESS_DAY_SHARE`, `ADDRESS_DAY_TOPICS` |
| S-206 | `wrangler.jsonc` sets `observability.enabled` to false: no Workers logs or traces, no Logpush; the relay writes no request logs. | S-76a | Account key pair (P-256) is the owner authority; the account id is the first 24 hex characters of its fingerprint (SHA-256 of the public coordinates). | S-76b | The account private key is stored encrypted in the account document (`keys.sealed:<fingerprint>`, so also in backups), with a key derived from the passphrase by PBKDF2 with its own salt and label. Until sealed, the private half stays in the creating device's IndexedDB | A device with the backup key must not be able to act as the owner; restore brings back the same account |

| S-76q | Account key passphrase uses PBKDF2 (the backup parameters, one passphrase for both) in slice 1; Argon2 later if a library earns its size | No new dependency yet |
| S-76r | **Bridge superseded by S-295b.** Existing accounts move to the fingerprint id at the first start of the updated build (`src/core/account-move.ts`): the account document is copied to `account/<fingerprint>` with `Y.applyUpdate`. Older builds only know the old id, so a paired device keeps the old document open, keeps it equal to the new one (`bridge`), keeps the pairing, sync-code messages and shared log under the old id, and leaves it out of backups. An unpaired device drops the old id. The old document goes when the account requires keys (slice 3) | Mixed versions keep syncing and nobody notices; copying one Yjs state on two devices converges |
| S-76s | Which account key everyone follows is decided by the document alone: `keys.chosen` (a fingerprint), written only while absent by the first device to settle, so Yjs resolves concurrent writes the same on every device; devices follow it and never use their own current id or the untrusted `at` time. Every key is published as `keys.account:<fingerprint>`. A paired device makes no key until a peer has sent it the account document since the update; a joining device with no data makes none; unpaired and new accounts make theirs at once. A device drops every private key it made that is not chosen. The one exception: a device whose passphrase was just typed may replace an **unsealed** chosen key whose creator was removed or left, by sealing a new key and making it chosen. Not when the creator is this device after it lost its keys: other devices cannot check that claim (owner, #256), so Backups says to remove this device on another one first. A creator whose storage was silently cleared still counts as present, so Backups says where the key was made and to remove that device in Devices first. Accounts that set a backup passphrase before the update are asked once in Backups (a line on Devices links there). A change of `chosen` is checked on receive (S-256d) | All devices converge on one key; a late or grinding device cannot move a settled account |
| S-283 | **Superseded by S-295b.** This build is the rollback target for the account-id move (#255). `reverseAccountMove` (`src/core/migrations.ts`) runs on every start, before documents open: if `${STORAGE_PREFIX}-account-legacy` holds an id, the current account id (`-account`) goes back to it; the fingerprint document is left untouched. It is not version-gated because the device version may already be recorded. A build with account keys (#282) does not call it, and ships with `backupFirst` set. What a moved device leaves that this build tolerates: the `keys` map in the account document (unused), the synced flag (unused), the shared log (kept under the old id), the old document (bridged, so complete). One cost: the backup passphrase asks again once (its stored key is bound to the fingerprint id), and new backups go to the old id's folder. An unpaired device moved without a legacy id and stays on the fingerprint id, which this build handles as any id | After #282 the sync filter needs the current id to equal the paired id, so a plain `wrangler rollback` would stop moved devices syncing; with this build deployed first it does not |

| S-256 | Signed handshake: a certified device signs every offer and answer (topic, type, both ids, session id, time, packed session description) with its device key. | S-256b | Certificates on real devices from this slice (owner, #256): in compatible mode the device holding the account key (its creator before sealing, or any device for 5 minutes after the passphrase is typed) certifies every device that published keys and has no valid certificate, trust on first use as the sync code already is.
