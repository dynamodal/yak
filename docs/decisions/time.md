# Time tracking: decisions to review

Choices made while building `src/time/` that the owner may want to change.
Each row says what was decided, why, and how to change it.

| Decision | Why | How to change it |
| --- | --- | --- |
| A new `registerGlobal` hook in `src/app/registry.ts`, rendered by `App.tsx` above the navigation | The running-timer rule, the `timer:start-request` listener and the idle banner must work on every view, not only while the Timer view is open. The module contract only had views | Drop the hook and mount `TimeBackground` inside the Timer view, at the cost of the rule not running on other views. Other modules (backups) may add a similar hook, so expect a merge conflict to resolve once |
| The rule stops each older running entry at the start of the next later one (a chain), not all at the latest start | Stopped entries never overlap, and the result depends only on the set of running entries, so devices that see different subsets first still end at the same answer | `enforceSingleRunning` in `src/time/rule.ts` |
| Two devices that saw different subsets can leave a stopped entry overlapping the winner by a short time | The merge picks one of two concurrent writes to the same `stop` field. The count of running timers always ends at one, and all devices hold identical data | Accept it, or add a reconciliation pass that re-derives stops from all entries |
| The rule emits `timer:stopped` only for stops it applies on this device | Backups listen for stops. A stop that arrives from a remote device is that device's to announce | Emit from a Yjs observer on `stop` changes in `TimeBackground` |
| An entry belongs to the local day it started on and is not split at midnight | Matches how Toggl groups entries and keeps totals simple | `groupByDay` and `entriesInRange` in `src/time/stats.ts` |
| Times of an existing entry are edited with a draft and a Save button | `datetime-local` fires a change on each segment, so saving while typing would reject half-typed values | `TimeRange` in `src/time/entry-ui.tsx` |
| The description field is an uncontrolled input that follows its value only while not focused | A controlled input was reset by re-renders from sync and from the clock, and lost typed text | `DescriptionField` in `src/time/widgets.tsx` |
| Picking a project sets billable from the project, also when editing an existing entry | Same as Toggl. The checkbox can be changed afterwards | `setProject` in `FieldsForm` (`src/time/entry-ui.tsx`) |
| Tags are managed in one list per space for entries, notes and tasks (Projects page). The safe action is **Hide from pickers**: a hidden tag still shows on items and in reports (owner, 2026-10-17); stored in the space document, `hidden_tags` | A delete that strips every item is too easy to hit; hiding is reversible and loses nothing | `TagManager` (`src/app/views`), `src/core/hidden-tags.ts` |
| Rename merges when the new name exists; "Remove from all items" is labelled a bulk edit. Both show a count first and give one Undo | Entries store tag names, as in Toggl, so a name left behind would show a tag that no longer exists | `renameTag`, `deleteTag` in `src/time/catalog.ts`; `rewriteNoteTags` in `src/notes` |
| Bulk edits carry the origin `bulk-edit` and one Undo is a `Y.UndoManager` limited to that origin | The history banner must stay quiet for edits the person chose; Undo must not touch other edits | `src/core/bulk.ts`, `MEANT` in `src/core/history/watch.ts` |
| A project or client is archived by default; Delete only when unused, otherwise "Move … to" another one or none first, with one Undo | Deleting a used project would orphan its entries | `ProjectsView.tsx` |
| The tag `task` is not offered for rename or removal on notes | It marks a note as a task | `src/notes/tag-source.ts` |
| Entries are selected with a checkbox per row (shown after "Select", or after a Ctrl/Cmd click, Shift click or touch long press), a checkbox per day, and "Select all" for what the list shows. Selection state and the long press are shared in `src/app/selection.ts` so notes can use them | One mechanism for mouse, keyboard and touch; lists differ only in their rows | `BulkEntries` in `src/time/EntrySelection.tsx` |
| Bulk actions: set project, add or remove a tag, billable on or off, move dates (shift by days, or one date keeping times of day), move to another space, delete. Each is one transaction, one Undo, a count in the notice. Running entries are never changed. A grouped row selects all its entries | Same set as Toggl's bulk edit; one Undo is what makes a bulk action safe | `src/time/bulk-edit.ts` |
| A bulk project is matched by name in each entry's own space; an entry whose space has no such project is skipped and counted | Projects belong to a space (S17); a chosen project cannot apply across spaces by id | `setProject` |
| Moving entries to another space copies them (new id), maps the project by name (made in the target with its client when missing), makes the tags there, and marks the originals deleted without the restore stamp. Rates are private and not copied; a task link is dropped | An entry's space follows its project (S17); no copy stays behind (as N25) | `moveToSpace` |
| Tag names are unique ignoring case; two devices creating the same name show it once | Tag records are keyed by UUID, so concurrent creates make two records | `uniqueTagNames` in `src/time/catalog.ts` |
| Hours format is stored in the Personal space document, `settings.hours_format`, and changed only on the Settings page | The architecture says display settings are shared across devices. The selectors that used to sit on the Timer and Entries views were removed (owner question Q9) | See `docs/decisions/settings.md`. `week_start` is read from the same map through `src/core/settings.ts` |
| The "This week" list on the Timer view shows the days before today, with the week total in its heading | Today is already listed above it | `TimerView.tsx` |
| Idle detection uses a threshold of 10 minutes, the `visibilitychange` event and a one-second tick | The tick also catches a laptop that slept without a hide event. Chrome throttles hidden tabs to about one tick a minute, which stays below the threshold | `IDLE_THRESHOLD_MS` in `src/time/idle.ts` |
| Idle banner choices: keep, discard (stop at the moment the page was hidden), discard and continue | As specified. Nothing is changed until the user picks | `TimeBackground.tsx` |
| Deleting an entry shows a toast with Undo; the entry can be restored for 45 days (`RESTORE_WINDOW_DAYS`) | Deletes are soft, so Undo costs nothing and a confirmation would block the browser tests | `deleteEntry` toast in `src/time/entry-ui.tsx` |
| Starting a timer in one space stops a running timer in any other space | The running-timer rule spans all spaces. The Timer view shows the other space's timer with a Stop button | `startTimer` in `src/time/entries.ts` |
| The Projects page shows all spaces by default; it shares the Timer and Entries space filter (`app-space-filter`) | One filter across the time pages; rows carry a space label when more than one space is kept | `ProjectsView.tsx`, `useAllTime` |
| Adding a project or client picks its space (the last used one by default; fixed to the filter when one space is shown) | Items must not land in a space by accident | `ProjectsView.tsx` |
| Tags in All spaces are one row per name with per-space counts; hide, rename and remove ask which spaces, all checked by default | The same tag name in two spaces is one concept; one Undo covers every space touched | `TagManager.tsx` |
| Moving a project, client or tag to another space archives it in the source (a tag is hidden there) and creates it in the destination; nothing is deleted. A project keeps name, colour, billable and its private rate; its client is reused by name or created. Entries move with the project by default (untick to leave them); a client can take its projects. A name that exists there is merged into, or a project is made under a new name. One bulk edit, one Undo | Owner, 2026-10-19. An entry's space follows its project (S17); no deletes, so Undo and the source stay whole | `src/time/move-space.ts`, `src/core/move-tag.ts`; menu "Move to space…" on `ProjectsView` and `TagManager` |
| Projects & tags has a Select mode (the page-header toggle): tick projects, clients and tags, pick one space, "Move to space". Each item moves as it does alone; names that exist there are merged into (no rename in bulk); entries and a selected client's projects come along unless unticked; items already in the destination are left and counted. One bulk edit, one Undo (#193) | Moving many at once is the point of selecting; a per-item name prompt would defeat it. Merging never loses data and Undo restores all | `moveMany` in `src/time/move-space.ts`; `MoveSelectedBar` in `ProjectsView.tsx`; selection state in `src/app/selection.ts` |
| T248 | **Tablet rows (#248):** from 40rem to 58rem an entry row stacks like the phone one (description, then project and tags) but keeps the time range; the project name keeps its hover title | At 768 px the description and project shared one line and both were cut while the time column kept its width | `.te-main` media block in `time.css` |
| T-idle1 | **Idle prompt (pre-share fix):** being hidden is not away. The tick runs while the tab is hidden too, and only a gap over 10 minutes between ticks (device slept, page frozen) prompts. This replaces the "hide" event rule above. The running entry now also shows as a row in the Time list (editable start, deletable), replacing the bar-only rule X10; the empty text no longer claims "Nothing tracked" while a timer runs | A timer running in a background tab is normal use, and the old rule asked about every tab switch longer than 10 minutes. A hidden tab ticks about once a minute (below the threshold), so a real sleep still shows as a gap. A browser that freezes a hidden tab will also prompt on return, which is acceptable. The popover has no start field, so the list row is the way to fix a start or delete the running entry | `IdleTracker` in `src/time/idle.ts`; `TimeBackground.tsx`; `TimerView.tsx` |
| T-62 | **A timer without a project starts in the space of the entry made last** (`created_at`; amends X20), not the app's active space. Opening a note switches the active space but no longer moves the timer; with no entries yet, or when that space is not on this device, the active space is used. A chosen project's space still wins and becomes active. With several spaces the start popover has a Space picker showing that space and letting you change it (a chosen project's space or picked space becomes active). Continue paths already use the source entry's space | Following a note across spaces put a header Start in the wrong space, without the project (#62) | `timerSpace` in `src/time/timer-start.ts`; `TimerPopover.tsx` |
| T-60 | **The description field is a combobox of past work (#60; replaces the `<datalist>`).** In the timer popover, Add entry and the entry editor. Fuzzy match (`src/time/fuzzy.ts`, local, no dependency): every typed word must match, in any order, as a word start, inside a word, or (4+ letters) with one typo; project-name words count for less. One row per description + project + space, showing the newest such entry's project (client), tags and, with several spaces, the space; best match first, then most used, then newest; at most 8, across all spaces. Roles: `combobox` on the input with `aria-expanded`, `aria-controls`, `aria-activedescendant`; `listbox` of `option`s; focus stays in the input. ArrowDown/Up move, Enter picks the active row (otherwise Enter submits as before), Esc closes the list first, a click picks. A pick fills description, tags, billable and project (the project's space in the popover and Add entry; in the entry editor and while running only a project of the entry's own space) and does not start the timer, so Enter then starts with them. The list floats (`position: fixed`) so it never shifts the controls below or clips in the popover | Matches Toggl's continue and the Recent pick, but a fill-then-Start keeps one click from starting the wrong thing; the datalist matched prefixes only and looked different per browser | `DescriptionField` in `widgets.tsx`; `useCandidates` in `hooks.ts`; e2e in `scripts/e2e/time.mjs` |
